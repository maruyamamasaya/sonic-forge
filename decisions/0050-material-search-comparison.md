# 0050: 素材の注釈検索と同一区間の比較試聴
Date: 2026-10-19
Status: accepted

## Context
来歴付き素材保存に続き、ユーザーはタグ/メモの蓄積と検索、元曲/分離パートとの比較試聴を依頼した。

## Decision
SQLite schema v2へ移行し、既存の音声・来歴payloadを変更せず、material_annotations/tags/material_tagsを追加する。移行前にSQLite backup APIでv1の一貫したDBコピーを保存し、DDL/検索キー初期化/版更新はtransactionで行う。未知版・破損は保持して拒否する。
名前/元曲名/タグ/メモをUnicode互換正規化・大小/幅統一した索引で部分一致検索し、タグIDによる完全一致絞込と50件単位のページングを行う。SQLはbindし、LIKE記号は通常の文字として検索する。空白区切りの複数語はAND条件。音声を検索時にデコードしない。
比較試聴は保存範囲と同じ長さの素材/元曲/stemの短いPCMを一時生成する。MainActorで小さいAVAudioPlayerを切替え、相対位置を維持。区間外の発音をUIタイマーだけで止めない。選択/検索変更、全停止、非アクティブ、画面終了で準備中の処理も無効化する。編集中の楽器や構成を置換しない。

## Alternatives and Consequences
単一payloadへの注釈追記は不変の来歴との境界が曖昧になり、検索のたびに全件デコードが必要になる。日本語の全文検索/音響embeddingは初期版には追加せず、SQLiteの正規化済み文字列検索を使う。LIKE部分一致のため全件索引走査は将来の規模評価が必要。
比較用長尺ファイルの時刻だけを変える案では選択末尾の音漏れを保証できない。短いPCMの生成には初回準備時間が必要だが、同じ素材内の切替では再生成しない。注釈は明示保存し、切替/閉鎖/編集へ渡す前に未保存確認を行う。検索中も編集フォームを保持して入力を失わない。
楽器v4、音声本体、元曲frameは変更しない。自動タグ/類似検索/削除/楽器への来歴埋込は別段階。仕様は[MATERIAL_LIBRARY](../MATERIAL_LIBRARY.md)。
