# macOSアプリの追加ルール

この配下はSwiftUI / AppKit / AVFoundationを使用する。共通ルールはルートAGENTS.md。
- メイン画面はWorkspaceView、選択設定はWorkspaceInspector、下段音符編集はClipNoteEditor（SelectedClipNotes/ClipNoteGrid）→EnsembleModel.editClipNotes/editNoteGroup、素材編集画面はStudioView、再生状態はPlayerModel、ファイル解析・合成はAudioAsset、範囲と表示状態はWaveformEditor、選択音声はSelectionAudio、楽器エンジンはSampleInstrument、鍵盤はInstrumentKeyboard、保存形式はInstrumentDocument、ADSRの状態計算はADSREnvelope、MIDI機器・受信とバイト解析はMIDIInput、演奏データ形式・検証はPerformanceDocument、演奏編集UIはPerformanceEditor、楽器一覧・試聴はInstrumentLibrary、一覧UIはLibraryView、AI生成の共通検証はPerformanceGeneration、接続はCodexPerformanceClient/OpenAIPerformanceClient、候補状態はPerformanceComposer、生成UIはPerformanceComposerView、編曲の形式/検証はArrangementGeneration、候補状態はArrangementComposer、確認UIはArrangementComposerView、複数パートの割り当て/時計/ミックスはEnsembleModel、パート別押鍵/ペダル所有権はEnsembleVoice、画面はEnsembleView、配置の計算/描画はEnsembleTimeline/EnsembleTimelineView、セクションの検証/編集はEnsembleSections/EnsembleSectionsView、共有楽器の複数演奏検証/編集はEnsembleClips/EnsembleClipEditor、構成保存形式はEnsembleDocument、全体WAVレンダーはEnsembleExportに分離する。
- UIと再生状態の更新はMainActor。波形解析・音源合成はバックグラウンドで行う。
- 波形は線形振幅。メーターのみdB表示。実測しないデバイス名・サンプルレートや架空の状態を表示しない。
- ファイル読み込みが失敗したら元の音源を保持し、エラーを表示する。元ファイルを書き換えない。
- デザイン変更はユーザーの指示を優先し、承認済みのメイン3列（左ライブラリ・中央タイムライン・右選択設定）と下部トランスポートを維持する。Sample Studioの中央波形・鍵盤・右設定も維持する。
- 検証はTESTING.mdのNative変更手順に従う。音が出ることと音質・遅延品質を保証することは区別する。

- 主要UIは日本語。JapaneseUI.swiftは表示用の変換と検索付き用語説明だけを扱う。保存キー/enum rawValue/ユーザーデータ名を翻訳しない。UI名の変更時はaccessibilityIdentifierとAI_OPERATIONSの対応を保ち、ツールチップと最小サイズも確認する。

- 音源分離はSeparationView（設定/試聴/採用）、SeparationModel（MainActorのジョブ/候補/試聴状態）、SeparationClient（Process/契約/音源検証）、同梱separation_worker.py（固定MLX）に分ける。採用した音はPlayerModel.useSeparatedAudioの所有コピーで保持し、候補の寿命から切り離す。詳細は[分離ガイド](../SEPARATION.md)。

- 来歴付き素材はMaterialOrigin/SeparationLease（分離jobの参照所有）、MaterialStore actor（SQLite3/管理音声/準備・commit・復元）、MaterialLibraryModel/View（検索/注釈/容量確認/一覧/比較試聴）とMaterialComparison（同一区間PCMの所有）に分ける。PlayerModel.openMaterialは検証後に全長波形と絶対frame選択を復元する。テストは一時MaterialStoreを注入し、本番Application Supportを変更しない。短いclipの再編集はframeOffsetで元曲位置へ写像する。waveformProvenanceと楽器化時点のinstrumentProvenanceを分離し、楽器v5/構成v12・履歴/AI編曲にも保持する。来歴なしはv4/v11。

- 素材注釈は来歴payloadと別のschema v2へ保存する。移行前はSQLite backup APIで退避しtransactionで移行。比較は短い同長PCMを用い、PlayerModelの全停止/他再生と排他にする。検索/選択/画面終了で準備を無効化し、未保存のタグ/メモを無確認で破棄しない。

- 素材のゴミ箱はschema v3のmaterial_trashだけで管理し、共有音声・来歴payload・親子関係を削除/更新しない。通常検索とゴミ箱を分け、ID指定の来歴参照は両方で維持する。移動/復元と表示切替で試聴を停止し、未保存注釈の確認を保つ。完全削除はMaterialDeletionのschema v4で別管理する。確認時の影響/容量を再検証し、tombstone/回収journalのcommit後に未参照音声だけ回収する。楽器の永続保護と開いた波形/比較のleaseを保ち、失敗分は未回収メニューで再確認する。

- 素材の永続保護解除はMaterialDeletionのprotectionReview/prepareRelease/releaseProtectionを使う。現在の楽器・構成/履歴・既知ファイルを再監査し、同一の使用中保護は解除しない。仮解除はrollbackし、確定時のsnapshot再検証後も保護行だけを削除する。音声回収は別途確認し、解除後の削除済み来歴への入口を残す。

- 複数素材の完全削除は選択ID集合全体で計算し、選択内の親子を残存参照にしない。選択外の素材・楽器・構成/履歴・leaseを保護し、hash単位で容量/回収を重複排除する。全件の来歴/注釈/journalを同じtransactionで確定し、部分回収失敗は既存の再確認経路に残す。

- サンプル仕上げはSamplePreparationProcessor（不変PCMコピーへの音量/フェード）→SamplePreparationAudio/Model（比較WAV所有/非同期/取消/試聴）→SamplePreparationView。PlayerModelは対象buffer identityを検査して採用し、基準音/ADSR/ループ/来歴を維持する。元の波形/ファイルは変更せず、加工PCMを既存楽器形式へ保存する。[仕様](../SAMPLE_PREPARATION.md)。
